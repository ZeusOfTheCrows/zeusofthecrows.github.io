CSS is Like a Zachtronics Game, Really

so first up – unlike a zt game, it's bollocks. it's inconsistent, confusing, and seemingly random. it's clearly been designed by multiple people over decades, each with a different goal in mind. why the fuck is currentColour the only value that's camelCase? in fact, i think it's the only required capital anywhere in css? there are at least 6 different ways of centring items, depending upon its direction and parent. i mean, just off the top of my head:

  • align-items: center;
  • margin-inline: auto;
  • text-align: center;
  • justify-content: center;
  • vertical-align: middle; /* why is this one not center? */
  • transform: translate(0, -50%);

there's also some really weird oversights? why is there no background-repeat: mirror;? i know it's a minor thing, but it feels like it would be easily implemented and, while less important now, very useful in the days when background repeating was more commonly utilised

more egregious omissions are things like

.position-sticky:stuck{}
which would allow one to target sticky elements that have reached their "stick" point and stuck — for example i could use this to adjust the corner radius of the floating on the logfile page when it hits the top
.grid-container:nth-column(2)
which would allow one to for example, set a maximum height or width for a specific grid row or column by location, rather than having to specify it on the child
.flex-item:wrapped
target flex (or grid) children that have wrapped (although this could be avoided if the above property existed, using .flex-container:not(:nth-column(1))). i would be able to use this on the homepage to only target the sidebar (to give it rounded top corners) if it has wrapped, rather than manually specifying a breakpoint (which is is inherently less maintainable)
theme-colour: currentColour;
i mean this one is just really annoying. it's a styling element that can only be declared in html. (<meta name=<"theme‑color" content="#ecd96f">) want to change it? use javascript. fuck you.
i mean, i'd like to set it to a custom property (--header-colour) but nuts to that, apparently. imagine how useful it could be in css

and, just like opus magnum, there is no "right" solution. it's about working around the (numerous) limitations to get as close as possible to the desired result. just as mentioned in this video, one can either meet the targets of clarity, concision, or ease / time to finish; but not all three simultaneously. all code is hard to read when it's written by someone else, but css i find particularly hard compared to its ease of understanding at the time of writing, especially as it requires holding 2+ files in ones head (as the structure of the related html file is important, as well as possible js files).

and to be honest, that's fun. trying to figure out the "best" way to solve this puzzle, for æsthetics & maintainability, is just as good as TIS-100, and it's free! and you get something out of it at the end (more than just a steam achievement, at least)

Accessibility considerations

Unstyled lists are not announced as lists by VoiceOver. If your content is truly a list but you would like to keep it unstyled, add a "list" role to the element: 

<ul role="list">
	<li>One</li>
	<li>Two</li>
	<li>Three</li>
</ul>

tailwind themselves highlight an issue with doing exactly the thing they're doing, but apparently don't have the introspection to, you know, not bloody do it
